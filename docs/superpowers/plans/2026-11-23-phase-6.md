# Phase 6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an outbound-only customer gateway, read-only enterprise connectors, OIDC SSO, security/evaluation hardening, recovery/load evidence, and deployment-only container packaging.

**Architecture:** Keep the existing PostgreSQL queue and tenant RLS as the control plane. A customer gateway long-polls over outbound HTTPS and executes only validated read plans locally; identity and connectors remain behind existing API/connector contracts. Native PostgreSQL remains the local/test environment, while container images are built in CI for deployment validation.

**Tech Stack:** TypeScript/Node 22, Fastify, pnpm, PostgreSQL 16, existing SQL guard and runner, OIDC authorization-code with PKCE, Dockerfiles/Compose for deployment validation only, Python 3.11 SQL parser.

**Spec:** `docs/phases/phase-6.md`

## Global Constraints

- Keep all eight frozen contracts unchanged.
- Use tenant-keyed PostgreSQL RLS; app and worker roles own no tables and cannot bypass RLS.
- Release 1 connectors remain read-only; no action credentials enter analytical code paths.
- Never store or log raw rows, credentials, authorization codes, model prompts, or direct identifier values.
- The customer-side gateway opens outbound connections only and introduces no broker or extra service.
- Local development and regular tests use native PostgreSQL 16; Docker is only for deployment and CI image validation.
- Use synthetic golden fixtures and generated fake rows only; no external IdP/CRM/lake/system credentials.
- Push every commit on branch `phase-6`; merge through a green PR.

## Review Focus

- Gateway enrollment, lease expiry and result replay must not allow duplicate or cross-tenant completion; test `c1_gateway_enrollment_is_single_use_and_tenant_bound` and `c5_gateway_claim_lease_and_result_replay_are_idempotent`.
- Private source inputs must never leave the customer network when gateway-only policy applies; test `c7_gateway_only_collation_keeps_input_bytes_inside_network`.
- Hostile metadata and SQL encodings must not expand a typed read plan; test `c3_adversarial_metadata_cannot_change_validated_plan` and `c3_sql_guard_rejects_mutation_and_multi_statement_bypass_attempts`.
- OIDC state, nonce, audience and issuer confusion must not establish the wrong identity; test `c1_oidc_pkce_state_nonce_audience_and_tenant_are_verified`.
- A backup that restores but misses recovery objectives is not acceptable; test `c5_backup_restore_drill_meets_recovery_objectives`.
- Compose defaults must not embed usable credentials or expose the customer gateway; test `phase6_deployment_images_build_without_local_docker_requirement`.
